# Fuxi ColorOS installer

Проект установщика ColorOS для Xiaomi 13 (`fuxi`). Оболочка **2.6.0**, профиль **PKG110 17.0.0.105(CN01), 30.10.2026**. Port by tomekcz.

## Запуск

Чистый установщик без прошивки: `releases/FUXI-INSTALLER-2.6.0-PKG110-BARE.zip` (около 4,7 МБ). В нём мастер и Windows ADB/fastboot/zstd; отсутствуют все образы images/ и TWRP. Сам по себе этот архив не готов к прошивке: сначала добавьте проверенные образы именно PKG110 из соответствующего полного комплекта. Исходный манифест сохранён, проверки целостности не отключаются. В Git находятся исходники, тесты, документация и манифест, без прошивки и бинарных утилит.

Сборка чистого архива: `python tools/build_release.py --kind bare`. После клонирования Git сначала импортируйте Windows-утилиты и остальные компоненты командой `python tools/import_assets.py "/path/to/unpacked/PKG110"`; они останутся локальными и игнорируются Git.

Распакуйте архив FULL. Windows: `FLASH.bat`. Linux, из папки установщика:

На Linux нужны Bash, системные `adb`, `fastboot`, `zstd`, GNU coreutils (`timeout`, `df`, `sha256sum`; вместо последнего допустим `shasum`). Windows-инструменты включены в архивы. Python требуется только для подготовки, сборки и тестирования комплекта.

```bash
bash START.sh                    # пошаговый мастер RU/EN/PL
bash flash.sh --clean            # чистая установка со стиранием данных
bash flash.sh --update           # обновление совместимого установленного порта
bash flash.sh --verify-only      # проверка без команд телефону
```

Обновление пропускает erase userdata/metadata и переразметку. Нужны существующий super 11 ГиБ, слот A и совместимые версии того же порта. Совместимость перехода автоматически не определяется.

Пункт 4 быстро проверяет наличие образов, свободное место и телефон, не перечитывая большой super. `OK` означает отдельное выполненное условие, `BLOCKED` — препятствие, `UNKNOWN` — непроверенное условие. Подтверждённого списка переходов между версиями и KSU/без root пока нет, поэтому совместимость всегда `UNKNOWN`. Пункт 3 и начало установки выполняют полную проверку SHA-256.

После ошибки видны последний этап, попытка записи и команды с успешным ответом. Пункт 6 сохраняет в `reports/` ZIP последней структурированной сессии: только фиксированные коды событий, без сырых логов, серийных номеров, личных путей и GPT-копий. На Linux для экспорта нужен `zip`; установка работает без него. Отчёт никуда автоматически не отправляется.

Подтверждения — y/n; Enter и EOF отменяют. Обе системы имеют меню RU/EN/PL, сводку перед записью, проверку файлов и диагностику без перезагрузки. После операции можно вернуться в меню. Выбор KSU/без root появляется при добавлении соседних комплектов; они пока не предоставлены. Подключение: `installer/BUILDS_RU.txt`. Инструкция для пользователя: `installer/QUICK_START.txt`.

Обе системы поддерживают чистую установку из A/B при super 11 ГиБ; расширение 9 → 11 ГиБ требует A. Активация A выполняется после успешных записей и стирания, затем проверяется. Обновление всегда требует A и не активирует слот. Команды имеют таймауты; временный sparse удаляется при штатном выходе и ошибке.

## Разметка

Проверяются модель, разблокировка, слот, размеры, хеши, GUID, GPT, резервная копия и занятые разделы. Допускаются две геометрии с сектором 4096:

| super / userdata | Начало super | Конец 9 ГиБ | Конец 11 ГиБ |
|---|---:|---:|---:|
| 32 / 33 | 854080 | 3213375 | 3737663 |
| 31 / 32 | 751680 | 3110975 | 3635263 |

При переразметке начало userdata сдвигается, его конец и уникальные GUID сохраняются. Расширение и восстановление размера стирают данные. GPT-копия не содержит личных файлов.

## Исходники и сборка

- `installer/` — единственный актуальный каталог исходников.
- `tools/` — импорт проверенных компонентов и сборка ZIP.
- `tests/` — Windows/Bash, пакеты/профили, меню, native-команды, sparse/LP и recovery/GPT без USB и реальных дисков.
- `docs/VALIDATION.md` — подтверждённые результаты и ограничения.
- `releases/` — локальные архивы и их SHA-256.

Исторические каталоги сохранены локально. Git содержит код, лицензии/notices и манифест; образы, EXE/DLL, ZIP, журналы и персональные GPT-копии исключены.

После клонирования импортируйте компоненты из полного комплекта именно этого PKG110:

```bash
python tools/import_assets.py "/path/to/unpacked/PKG110"
python tools/build_release.py --kind both
```

Импорт проверяет SHA-256. FULL содержит super.img.zst; INSTALLER — всё остальное. К INSTALLER перед прошивкой нужно добавить соответствующий super. Сборка проверяет CRC/SHA-256 каждого члена ZIP, не вызывает adb/fastboot и пишет только в `releases/`.

Намеренное обновление прошивки выполняется штатной подготовкой payload со структурными проверками. Не пересчитывайте хеши для обхода неизвестного повреждения. Инструкции: `installer/README_RU.txt`.

## Проверки

Python 3 и Bash, без образов и телефона:

```bash
python tests/run_all.py
```

После импорта: `cd installer` и `bash flash.sh --verify-only`. Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\flash.ps1 -VerifyOnly`.

`tools/messages.json` — общий каталог RU/EN/PL. После редактирования: `python tools/generate_messages.py`, затем `python tools/update_source_manifest.py`. Последняя команда обновляет только авторские текстовые файлы; ожидаемые хеши образов и vendor-компонентов сохраняются. GitHub Actions содержит матрицу Windows/Ubuntu; наличие workflow само по себе не означает успешный удалённый запуск.

Проект не назначает новую лицензию сторонним firmware/TWRP/platform-tools. Их уведомления и происхождение сохранены; права на распространение определяются авторами компонентов.
