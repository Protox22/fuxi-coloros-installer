# Установщик 2.6.0 — диагностика и помощь

Продолжение рефакторинга 2.5.0. Сохраняется терминальный мастер RU/EN/PL для Windows и Linux; Python и графические библиотеки для установки не требуются.

## Изменения

- Пункт 4 проверяет скрипты/профиль, наличие образов, свободное место и доступность инструментов. В fastboot отдельно оцениваются слот, размер super и разблокировка для чистой установки и обновления. Диагностика не перезагружает телефон и не выполняет записи.
- Большие образы при быстрой диагностике не хешируются. В Windows продолжают проверяться комплектные исполняемые инструменты. Целостность прошивки обозначена UNKNOWN; пункт 3 и штатная установка сохраняют полный SHA-256 контроль.
- У пользователя пока нет подтверждённого списка совместимых переходов. Совместимость обновления остаётся UNKNOWN, включая переходы KSU/без root. Технический OK не является разрешением на прошивку. Режим обновления сохраняет прежнее ручное подтверждение совместимости.
- Структурированный журнал записывает попытку мутации до запуска native-команды и успешный ответ после её завершения. После ошибки показаны этап, последняя попытка и успешные команды. Сбой диагностики до записи явно отличается от прерывания записи. Успешный ответ не доказывает загрузку Android; started без done может означать частичную запись.
- Прерывание PowerShell, включая остановку pipeline как при Ctrl+C, не получает статус finished: успех записывается только по завершении операции. Для незавершённой сессии сохраняется unfinished; при принудительном завершении процесса последнего результата может не быть вообще.
- Пункт 6 формирует ZIP последней подходящей сессии 2.6 в reports/. Экспорт включает только два файла: events.tsv с фиксированными кодами из разрешённого списка и README.txt. Сырые журналы, серийный номер, пути, образы и GPT-копии не включаются. Отправка только вручную.
- Экспорт пропускает собственные предыдущие сессии, связанные и слишком большие файлы, чужие заголовки и неизвестные строки. Поддерживает LF/CRLF. Занятый установщик блокирует экспорт. Ошибка архивации очищает только собственный незавершённый архив. reports/ исключён из упаковки и подготовки payload.
- Windows создаёт ZIP средствами .NET. Linux использует zip только для необязательного экспорта отчёта; отсутствие zip не мешает установке.

## Воспроизведение

`python tests/run_all.py` запускает сценарии с подставными adb/fastboot и небольшими искусственными образами. `python tools/verify_release.py` проверяет настоящий локальный PKG110, используя только VerifyOnly, проверку заголовков и потоковый разбор zstd/sparse/LP. `python tools/build_release.py --kind both` создаёт новые архивы с проверкой CRC/SHA-256 каждого файла.

В локальных Bash-тестах экспорта на Windows отсутствующий zip заменён тестовым Python ZIP backend; реальные ZIP Windows создаются штатным .NET. Нативная команда zip должна дополнительно проверяться на Linux (CI устанавливает её).

## Границы

Git Bash на Windows не заменяет нативный Linux. Локально нет настроенного Linux/USB стенда; workflow Windows/Ubuntu подготовлен, но удалённо не запускался. Реальная прошивка, Android recovery, драйверы, доступность данных и загрузка Android этим прогоном не подтверждаются. Автоматического возобновления и отката частичной записи нет.

Образы прошивки, firmware.conf, vendor-компоненты и scripts/prepare-super.sh не изменяются в 2.6.
