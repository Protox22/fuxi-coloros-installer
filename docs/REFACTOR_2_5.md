# Установщик 2.5.0 — 2 ноября 2026

В Windows и Linux теперь один понятный путь: открыть мастер, выбрать чистую установку или обновление, проверить комплект и телефон, прочитать план и подтвердить запись. На Linux мастер запускается командой `bash START.sh` или `bash flash.sh`; на Windows — `FLASH.bat`. Python для установки не требуется.

## Что изменилось

- Мастер RU/EN/PL на обеих системах. Переводы имеют один исходник `tools/messages.json`, из него генерируются PowerShell/Bash-файлы без дополнительных зависимостей пользователя.
- После операции можно вернуться в меню. Отсутствующие дополнительные сборки не добавляют лишний шаг. Существующие KSU/no-root комплекты проверяются по маркеру и совпадению скриптов.
- Перед записью показаны комплект, слот, размер super, требуемая база и последствия. Пустой ответ/EOF отменяет действие; неверный ответ повторяет вопрос. Отмена до записи имеет отдельный код 2.
- Добавлена диагностика Linux. Обе системы читают данные телефона без reboot/flash/erase. Полная проверка пакета отделяет готовую прошивку от установщика с отсутствующим super.
- Linux поддерживает чистую установку из B при уже существующих 11 ГиБ, как Windows. Переключение на A происходит после успешной записи и стирания; слот проверяется перед reboot. Расширение из 9 ГиБ и обновление требуют A.
- Команды имеют ограничение времени. Windows читает stdout/stderr одновременно, показывает сообщение при длительном ожидании и принудительно завершает зависший процесс. Bash использует GNU timeout с дополнительным принудительным завершением через 5 секунд.
- Непонятный вывод ADB, включая ошибки прав USB, теперь останавливает операцию. Проверки пакета отклоняют неоднозначные пути, дубли с разным регистром и ссылки внутри комплекта.
- Временный sparse удаляется при штатном выходе, отмене и ошибке. Журналы и GPT-копии сохраняются; повторные операции Windows получают уникальные имена журналов.
- Сборщик проверяет обязательные файлы, исключает журналы/копии GPT, не перезаписывает существующие выпуски и удаляет собственный незавершённый ZIP при ошибке.

Тесты используют синтетические прошивки, подставные native-процессы и искусственные GUID. Они не вызывают настоящие adb/fastboot и не открывают блочные устройства. Для sparse/LP создаются собственные небольшие метаданные двух разделов, исходная прошивка для основной тестовой матрицы не нужна.

Воспроизводимый запуск: `python tests/run_all.py`. Журналы и машинный отчёт сохраняются в `tests/.work/`. Сводка выполненных групп: `docs/TEST_RESULTS_2_5.json`. Отдельная проверка полного локального PKG110: `python tools/verify_release.py`.

## Границы результата

Проверено локально на Windows: Windows PowerShell 5.1, PowerShell 7 и Git Bash. Git Bash не является нативным Linux. Добавлен workflow для Windows/Ubuntu; удалённый запуск GitHub Actions в этой работе не выполнялся. Linux USB/udev, драйверы Windows, настоящий Android recovery, прошивка телефона и запуск Android не подтверждены этими тестами.

Сами образы, firmware.conf, vendor-компоненты и `scripts/prepare-super.sh` не изменялись. Режим обновления по-прежнему требует совместимый установленный порт того же варианта root: автоматического определения совместимости версий нет. Сохранение userdata/metadata не гарантирует доступность данных после смены ОС. Отмена после подготовки recovery/AVB не откатывает уже записанные разделы; автоматического возобновления/отката нет.

Справка о подключении Android/udev основана на [официальной документации Android](https://developer.android.com/studio/run/device). Значение current-slot, is-userspace и set_active сверено с [исходниками fastboot](https://android.googlesource.com/platform/system/core/+/master/fastboot/fastboot.cpp).
